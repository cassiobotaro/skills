```
   1  **Um mutex (de *mutual exclusion*) é um cadeado: só uma goroutine por vez pode estar na parte do código que ele protege, e as outras esperam.**
   2  
   3  Vou assumir que você conhece `async/await` e o event loop do JavaScript, mas não threads nem concorrência paralela. Se já souber, me diga e eu ajusto.
   4  
   5  **Por que isso não existia no seu JavaScript**
   6  
   7  O JS roda o seu código em uma thread só. Entre um `await` e outro, nada mais mexe nas suas variáveis. Em Go, goroutines podem rodar ao mesmo tempo em núcleos diferentes. Duas delas podem mexer na mesma variável no mesmo instante, e o resultado fica errado.
   8  
   9  **Um caso concreto**
  10  
  11  ```go
  12  package main
  13  
  14  import (
  15  	"fmt"
  16  	"sync"
  17  )
  18  
  19  func main() {
  20  	contador := 0
  21  	var wg sync.WaitGroup
  22  
  23  	for i := 0; i < 1000; i++ {
  24  		wg.Add(1)
  25  		go func() {
  26  			defer wg.Done()
  27  			contador++ // sem proteção
  28  		}()
  29  	}
  30  
  31  	wg.Wait()
  32  	fmt.Println(contador) // quase nunca é 1000
  33  }
  34  ```
  35  
  36  `contador++` parece uma operação só, mas são três passos: ler o valor, somar 1 e gravar. Suponha que duas goroutines leiam `7` ao mesmo tempo. As duas gravam `8`, e um incremento se perdeu. Isso se chama *data race*.
  37  
  38  Com um mutex, só uma goroutine por vez executa o trecho entre `Lock` e `Unlock`:
  39  
  40  ```go
  41  var mu sync.Mutex
  42  contador := 0
  43  
  44  // dentro de cada goroutine:
  45  mu.Lock()
  46  contador++
  47  mu.Unlock()
  48  ```
  49  
  50  Agora o resultado é sempre 1000. As goroutines passam pelo incremento uma de cada vez. Você perde um pouco de velocidade nesse trecho, e só nele.
  51  
  52  **Como se usa na prática**
  53  
  54  - O mutex fica junto do dado que protege, normalmente numa struct, e todo acesso a esse dado passa por `Lock`/`Unlock`.
  55  - O costume é usar `defer mu.Unlock()` logo depois do `Lock()`, para o cadeado ser liberado mesmo se a função sair cedo.
  56  - Esquecer o `Unlock` trava as outras goroutines para sempre (*deadlock*).
  57  - Você pode achar data races com `go run -race` ou `go test -race`.
  58  
  59  **O que esta versão deixa de fora**
  60  
  61  Existem `sync.RWMutex` (muitos leitores ou um escritor), `sync/atomic` (para um contador simples como o do exemplo) e canais, que são a alternativa idiomática em Go quando você quer passar dados entre goroutines em vez de compartilhá-los. Vale olhar isso quando seu caso for mais que "proteger uma variável".

  64
