## The reply given to the user

```
   1  **Short version:**
   2  - **Concurrency** means juggling several tasks, so that they overlap in time. Only one of them may actually be running at any instant.
   3  - **Parallelism** means several tasks literally running at the same instant, on different CPU cores.
   4  
   5  **Analogy:** One cook with three pots on the stove. While the pasta boils, they chop vegetables, then stir the sauce. Only one thing gets attention at a time, but all three dishes make progress. That's concurrency. Now hire three cooks, one per pot, all working at once. That's parallelism.
   6  
   7  Concurrency is about how you *structure* work, so you don't sit idle while waiting. Parallelism is about how you *execute* work, so you use more than one core.
   8  
   9  **What this means for your cleanup scripts**
  10  
  11  The first question is what your script spends its time on.
  12  
  13  1. **Waiting (I/O-bound):** downloading files, calling APIs, querying a database, reading many files from a slow disk. The CPU is mostly idle. Concurrency fixes this. While one request waits, you start another.
  14     - Tools: `threading`, `concurrent.futures.ThreadPoolExecutor`, or `asyncio`.
  15     - Example: fetching 500 URLs. Sequentially that takes 500 × latency. With 20 threads, it takes roughly 25 × latency.
  16  
  17  2. **Computing (CPU-bound):** heavy regex over millions of rows, parsing, hashing, number crunching in pure Python. The CPU is busy the whole time. Only parallelism helps, because you need more cores working.
  18     - Tool: `multiprocessing` or `concurrent.futures.ProcessPoolExecutor`.
  19     - Why not threads? Standard CPython has the GIL, which lets only one thread run Python bytecode at a time. Threads give you concurrency but not parallelism for CPU work. Processes each have their own interpreter, so they really do run in parallel. (Recent Python versions have an optional free-threaded build, but processes are still the safe default.)
  20  
  21  ```python
  22  from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor
  23  
  24  # I/O-bound: concurrency via threads
  25  with ThreadPoolExecutor(max_workers=20) as pool:
  26      results = list(pool.map(download, urls))
  27  
  28  # CPU-bound: parallelism via processes
  29  with ProcessPoolExecutor() as pool:
  30      results = list(pool.map(clean_chunk, chunks))
  31  ```
  32  
  33  The two APIs are nearly identical, so switching is easy.
  34  
  35  **Practical advice**
  36  
  37  - Don't reach for either one until the script is actually too slow. For most cleanup jobs, a plain loop is fine.
  38  - If you do need speed, measure first. Is the time spent waiting or computing? Something like `time python script.py` shows this. If "real" time is much bigger than "user" time, you're waiting (I/O). If they're about equal, you're CPU-bound.
  39  - If you use pandas, vectorized operations (avoiding Python-level loops) usually beat both approaches, with less complexity.
  40  
  41  **One-line memory aid:** concurrency is *dealing with* many things at once. Parallelism is *doing* many things at once.
```
