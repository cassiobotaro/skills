## The reply given to the user

```
   1  **Short version:**
   2  - **Concurrency** means juggling several tasks so they overlap in time. They take turns, and only one may be running at any instant.
   3  - **Parallelism** means actually running several tasks at the same moment, on different CPU cores.
   4  
   5  **An analogy.** One cook is making soup and bread. While the soup simmers, they knead the dough. That's concurrency: one cook, two tasks in progress, switching whenever one is waiting. Two cooks, one on soup and one on bread, working at the same time is parallelism.
   6  
   7  Concurrency is about *structuring* work so waiting time isn't wasted. Parallelism is about *executing* work simultaneously to go faster.
   8  
   9  **What this means in Python for data cleanup**
  10  
  11  The kind of slowness you have decides which tool to use:
  12  
  13  | Your script is slow because it... | Problem type | Tool |
  14  |---|---|---|
  15  | waits on files, network, APIs, or a database | I/O-bound | concurrency: `threading`, `asyncio`, or `concurrent.futures.ThreadPoolExecutor` |
  16  | crunches numbers, parses, or transforms lots of data | CPU-bound | parallelism: `multiprocessing` or `concurrent.futures.ProcessPoolExecutor` |
  17  
  18  Python's GIL (Global Interpreter Lock) lets only one thread run Python code at a time. So threads give you concurrency, not parallelism, for CPU work. They still help when the program is mostly waiting, because a waiting thread releases the lock. To use several cores, you need separate processes.
  19  
  20  **Examples**
  21  
  22  I/O-bound, such as fetching 100 URLs. Threads overlap the waiting:
  23  ```python
  24  from concurrent.futures import ThreadPoolExecutor
  25  import requests
  26  
  27  def fetch(url):
  28      return requests.get(url).text
  29  
  30  with ThreadPoolExecutor(max_workers=10) as pool:
  31      pages = list(pool.map(fetch, urls))
  32  ```
  33  
  34  CPU-bound, such as cleaning 50 big CSV files. Processes use all cores:
  35  ```python
  36  from concurrent.futures import ProcessPoolExecutor
  37  
  38  def clean_file(path):
  39      ...  # read, transform, write
  40  
  41  if __name__ == "__main__":
  42      with ProcessPoolExecutor() as pool:
  43          list(pool.map(clean_file, paths))
  44  ```
  45  
  46  Both use the same `pool.map` interface, so switching between them is a one-word change.
  47  
  48  **Practical advice**
  49  - If your scripts finish in seconds, you probably need neither. Don't add this complexity without a reason.
  50  - If you're cleaning many independent files, `ProcessPoolExecutor` is usually the easiest win.
  51  - With pandas or polars, vectorized operations are often faster than either approach, so try those first.
  52  - Measure before and after. Parallelism has overhead and can be slower for small jobs.
  53  
  54  To remember it: **concurrency is about dealing with many things at once, and parallelism is about doing many things at once.**
```
