## The reply given to the user

```
   1  Um **mutex** (de *mutual exclusion*, exclusão mútua) é uma trava que garante que só uma goroutine por vez execute um trecho de código.
   2  
   3  ## Por que você precisa disso
   4  
   5  No JavaScript você quase nunca pensa nisso, porque o código roda numa única thread com event loop. Entre um `await` e outro, ninguém mexe nas suas variáveis.
   6  
   7  Em Go, goroutines rodam de verdade em paralelo, em várias threads do sistema. Se duas delas mexem na mesma variável ao mesmo tempo, você tem uma **race condition**:
   8  
   9  ```go
  10  var contador int
  11  
  12  func main() {
  13      var wg sync.WaitGroup
  14      for i := 0; i < 1000; i++ {
  15          wg.Add(1)
  16          go func() {
  17              defer wg.Done()
  18              contador++ // PERIGO: não é atômico
  19          }()
  20      }
  21      wg.Wait()
  22      fmt.Println(contador) // quase nunca dá 1000
  23  }
  24  ```
  25  
  26  `contador++` parece uma operação só, mas são três: ler, somar, escrever. Duas goroutines podem ler o mesmo valor e uma sobrescreve o resultado da outra.
  27  
  28  ## A solução: `sync.Mutex`
  29  
  30  ```go
  31  var (
  32      contador int
  33      mu       sync.Mutex
  34  )
  35  
  36  func main() {
  37      var wg sync.WaitGroup
  38      for i := 0; i < 1000; i++ {
  39          wg.Add(1)
  40          go func() {
  41              defer wg.Done()
  42              mu.Lock()         // só passa quem pegar a trava
  43              contador++
  44              mu.Unlock()       // libera para a próxima
  45          }()
  46      }
  47      wg.Wait()
  48      fmt.Println(contador) // sempre 1000
  49  }
  50  ```
  51  
  52  Pense numa porta de banheiro com chave: quem pega a chave (`Lock`) entra, os outros esperam na fila, e quando a pessoa sai e devolve a chave (`Unlock`), o próximo entra.
  53  
  54  ## Boas práticas
  55  
  56  - **Use `defer mu.Unlock()`** logo após o `Lock()`. Assim a trava é liberada mesmo se a função der `return` cedo ou panicar:
  57    ```go
  58    mu.Lock()
  59    defer mu.Unlock()
  60    ```
  61  - **Mantenha a seção crítica pequena.** Quanto mais tempo você segura a trava, mais as outras goroutines ficam esperando.
  62  - **Agrupe o mutex com o dado que ele protege**, numa struct:
  63    ```go
  64    type Contador struct {
  65        mu sync.Mutex
  66        n  int
  67    }
  68  
  69    func (c *Contador) Inc() {
  70        c.mu.Lock()
  71        defer c.mu.Unlock()
  72        c.n++
  73    }
  74    ```
  75  - **Nunca copie um mutex** depois de usá-lo. Passe a struct por ponteiro.
  76  - **Não faça `Lock` duas vezes na mesma goroutine** sem `Unlock` no meio: isso trava o programa (deadlock).
  77  - Se há muita leitura e pouca escrita, existe o `sync.RWMutex`, que permite várias leituras simultâneas.
  78  
  79  ## Dica para quem vem do JS
  80  
  81  Go tem um lema: *"Não comunique compartilhando memória; compartilhe memória comunicando."* Em muitos casos, em vez de mutex, dá para usar **channels**. Mas para proteger um estado simples, como um contador ou um cache, o mutex é mais direto e perfeitamente idiomático.
  82  
  83  Para detectar race conditions, rode seu código com `go run -race main.go` ou `go test -race`.
```
