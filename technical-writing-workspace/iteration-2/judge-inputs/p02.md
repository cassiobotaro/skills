```
   1  # Export pipeline
   2  
   3  This page describes what happens to an export request.
   4  
   5  ## Request
   6  
   7  When an export is requested, the payload is validated. Requests above 100,000 rows are
   8  rejected. If the payload is valid, a job is enqueued and a `202` is returned.
   9  
  10  ## Processing
  11  
  12  The job is picked up and the CSV file is generated. The file is encrypted before it is
  13  uploaded to the bucket. If something goes wrong, the job is retried up to three times,
  14  after which it is moved to the dead-letter queue.
  15  
  16  ## Delivery
  17  
  18  Once the upload is done, a download link is sent by email. The link is expired after
  19  24 hours.
  20  
  21  ## Backups
  22  
  23  Backups of the bucket are rotated weekly.
```

### exporter/worker.py

```
   1  import json
   2  import os
   3  
   4  import boto3
   5  import pika
   6  from cryptography.fernet import Fernet
   7  
   8  from exporter.notifier import notify
   9  
  10  MAX_ATTEMPTS = 3
  11  
  12  
  13  def build_csv(job: dict) -> bytes:
  14      rows = [f"{job['account_id']},{n}" for n in range(job.get("rows", 0))]
  15      return "\n".join(rows).encode()
  16  
  17  
  18  def handle(channel, method, properties, body) -> None:
  19      job = json.loads(body)
  20      attempts = (properties.headers or {}).get("x-attempts", 0) + 1
  21      try:
  22          data = Fernet(os.environ["EXPORT_KEY"]).encrypt(build_csv(job))
  23          key = f"{job['account_id']}/{method.delivery_tag}.csv.enc"
  24          boto3.client("s3").put_object(Bucket=os.environ["EXPORT_BUCKET"], Key=key, Body=data)
  25          notify(job["account_id"], key)
  26      except Exception:
  27          target = "exports.dead" if attempts >= MAX_ATTEMPTS else "exports"
  28          channel.basic_publish(
  29              exchange="",
  30              routing_key=target,
  31              body=body,
  32              properties=pika.BasicProperties(headers={"x-attempts": attempts}),
  33          )
  34      channel.basic_ack(method.delivery_tag)
  35  
  36  
  37  def main() -> None:
  38      connection = pika.BlockingConnection(pika.URLParameters(os.environ["QUEUE_URL"]))
  39      channel = connection.channel()
  40      channel.basic_consume(queue="exports", on_message_callback=handle)
  41      channel.start_consuming()
  42  
  43  
  44  if __name__ == "__main__":
  45      main()
```

   1  # exporter
   2  
   3  `exporter` turns an export request into an encrypted CSV file and emails the requester a
   4  download link that expires after 24 hours. It has two processes: a FastAPI gateway that
   5  accepts requests, and a worker that builds the file, uploads it to S3, and sends the email
   6  through SES. The two communicate through RabbitMQ.
   7  
   8  This README covers running the two processes locally and requeueing failed exports. For
   9  what happens to a request from end to end, read [docs/pipeline.md](docs/pipeline.md).
  10  
  11  ## Prerequisites
  12  
  13  - Python 3.12 or later
  14  - [uv](https://docs.astral.sh/uv/)
  15  - A RabbitMQ server that has the queues `exports` and `exports.dead`. The code does not
  16    declare them.
  17  - An S3 bucket and an SES sender address that the worker can reach with AWS credentials
  18  
  19  ## Run it
  20  
  21  1. Install the dependencies:
  22  
  23     ```bash
  24     make setup
  25     ```
  26  
  27  2. Set the environment variables. The gateway reads `QUEUE_URL`. The worker reads all four.
  28  
  29     | Variable | Holds |
  30     |---|---|
  31     | `QUEUE_URL` | The RabbitMQ connection URL |
  32     | `EXPORT_KEY` | The Fernet key that encrypts each CSV file |
  33     | `EXPORT_BUCKET` | The S3 bucket that stores the encrypted files |
  34     | `MAIL_FROM` | The SES sender address of the download email |
  35  
  36  3. Start the gateway on port 8080:
  37  
  38     ```bash
  39     make run-gateway
  40     ```
  41  
  42  4. In a second terminal, start the worker:
  43  
  44     ```bash
  45     make run-worker
  46     ```
  47  
  48  5. In a third terminal, request an export:
  49  
  50     ```bash
  51     curl -X POST localhost:8080/exports \
  52       -H 'Content-Type: application/json' \
  53       -d '{"account_id": "acme", "rows": 10}'
  54     ```
  55  
  56     The gateway answers `202` with `{"status": "queued"}`. When the worker finishes, an
  57     email with the download link goes to `acme@accounts.example.com`.
  58  
  59  The gateway answers `422` when `account_id` is missing and `413` when `rows` is above
  60  100,000.
  61  
  62  ## Requeue failed exports
  63  
  64  The worker retries a failed job up to three times, then moves it to `exports.dead`. After
  65  you fix the cause, move the messages back to `exports` with `scripts/requeue_dead.py`.
  66  Set `QUEUE_URL` first.
  67  
  68  To count the messages without moving them:
  69  
  70  ```bash
  71  uv run python scripts/requeue_dead.py --dry-run
  72  ```
  73  
  74  To move at most 50 messages (the default limit is 100):
  75  
  76  ```bash
  77  uv run python scripts/requeue_dead.py --limit 50
  78  ```
  79  
  80  The script prints `moved <n> message(s)`, or `would move <n> message(s)` with `--dry-run`.
  81  
  82  The Prometheus rule `ExportsDeadLetterHigh` in [deploy/alerts.yaml](deploy/alerts.yaml)
  83  pages when `exports.dead` holds more than 10 messages for 5 minutes.
  84  
  85  ## Test
  86  
  87  ```bash
  88  make test
  89  ```
  90  
  91  This runs `pytest -q`.
