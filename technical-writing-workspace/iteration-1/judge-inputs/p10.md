  23  Backups of the bucket are rotated weekly.

### exporter/worker.py

```
   1  import json
   2  import os
   3  
   4  import boto3
   5  import pika
   6  from cryptography.fernet import Fernet
   7  
   8  from exporter.notifier import notify
   9  
  10  MAX_ATTEMPTS = 3
  11  
  12  
  13  def build_csv(job: dict) -> bytes:
  14      rows = [f"{job['account_id']},{n}" for n in range(job.get("rows", 0))]
  15      return "\n".join(rows).encode()
  16  
  17  
  18  def handle(channel, method, properties, body) -> None:
  19      job = json.loads(body)
  20      attempts = (properties.headers or {}).get("x-attempts", 0) + 1
  21      try:
  22          data = Fernet(os.environ["EXPORT_KEY"]).encrypt(build_csv(job))
  23          key = f"{job['account_id']}/{method.delivery_tag}.csv.enc"
  24          boto3.client("s3").put_object(Bucket=os.environ["EXPORT_BUCKET"], Key=key, Body=data)
  25          notify(job["account_id"], key)
  26      except Exception:
  27          target = "exports.dead" if attempts >= MAX_ATTEMPTS else "exports"
  28          channel.basic_publish(
  29              exchange="",
  30              routing_key=target,
  31              body=body,
  32              properties=pika.BasicProperties(headers={"x-attempts": attempts}),
  33          )
  34      channel.basic_ack(method.delivery_tag)
  35  
  36  
  37  def main() -> None:
  38      connection = pika.BlockingConnection(pika.URLParameters(os.environ["QUEUE_URL"]))
  39      channel = connection.channel()
  40      channel.basic_consume(queue="exports", on_message_callback=handle)
  41      channel.start_consuming()
  42  
  43  
  44  if __name__ == "__main__":
  45      main()
```

   1  # exporter
   2  
   3  A service that builds CSV exports in the background. The gateway accepts an export request and queues it. The worker generates the CSV, encrypts it, uploads it to S3, and emails the requester a download link.
   4  
   5  For the request lifecycle in prose, see [docs/pipeline.md](docs/pipeline.md).
   6  
   7  ## How it works
   8  
   9  1. `POST /exports` (the gateway, `exporter/gateway.py`) validates the payload and publishes it to the `exports` RabbitMQ queue. It returns `202 {"status": "queued"}`.
  10  2. The worker (`exporter/worker.py`) consumes `exports`, builds the CSV, encrypts it with Fernet, and uploads it to the S3 bucket as `<account_id>/<delivery_tag>.csv.enc`.
  11  3. The notifier (`exporter/notifier.py`) creates a presigned S3 URL valid for 24 hours. It emails the URL through SES to `<account_id>@accounts.example.com`.
  12  4. If processing fails, the worker republishes the job with an incremented `x-attempts` header. On the third failed attempt the job goes to `exports.dead`.
  13  
  14  ## Requirements
  15  
  16  - Python 3.12 or later
  17  - [uv](https://docs.astral.sh/uv/)
  18  - A RabbitMQ broker with the `exports` and `exports.dead` queues. The code does not declare them, so create them beforehand.
  19  - An S3 bucket and AWS credentials that can write to it, sign `get_object` URLs, and send mail through SES.
  20  
  21  ## Setup
  22  
  23  ```bash
  24  make setup
  25  ```
  26  
  27  ## Configuration
  28  
  29  Both processes read their configuration from environment variables.
  30  
  31  | Variable | Used by | Purpose |
  32  |---|---|---|
  33  | `QUEUE_URL` | gateway, worker, `scripts/requeue_dead.py` | AMQP URL of the RabbitMQ broker |
  34  | `EXPORT_BUCKET` | worker, notifier | S3 bucket for the encrypted files |
  35  | `EXPORT_KEY` | worker | Fernet key used to encrypt each file |
  36  | `MAIL_FROM` | notifier | Sender address for the SES email |
  37  
  38  boto3 reads AWS credentials and region from its usual sources.
  39  
  40  ## Running
  41  
  42  Start the gateway and the worker in separate terminals:
  43  
  44  ```bash
  45  make run-gateway   # HTTP API on port 8080
  46  make run-worker    # queue consumer
  47  ```
  48  
  49  Request an export:
  50  
  51  ```bash
  52  curl -X POST localhost:8080/exports \
  53    -H 'content-type: application/json' \
  54    -d '{"account_id": "acme", "rows": 500}'
  55  ```
  56  
  57  | Status | Meaning |
  58  |---|---|
  59  | `202` | The job was queued |
  60  | `422` | `account_id` is missing |
  61  | `413` | `rows` is above 100,000 |
  62  
  63  ## Tests
  64  
  65  ```bash
  66  make test
  67  ```
  68  
  69  ## Operations
  70  
  71  **Failed exports.** A job that fails three times lands in `exports.dead`. The Prometheus alert `ExportsDeadLetterHigh` (`deploy/alerts.yaml`) pages when the queue holds more than 10 messages for 5 minutes.
  72  
  73  **Requeueing.** After you fix the cause, move messages back to `exports`:
  74  
  75  ```bash
  76  uv run python scripts/requeue_dead.py --dry-run    # count the messages, move nothing
  77  uv run python scripts/requeue_dead.py --limit 50   # move at most 50 (default 100)
  78  ```
  79  
  80  The script needs `QUEUE_URL`. Requeued messages are published without the `x-attempts` header, so they get three new attempts.
  81

  85  exporter/   gateway.py (API), worker.py (consumer), notifier.py (email)

  88  docs/       pipeline.md
  89  ```
