Create a sequence diagram of our password reset flow for the API docs (it will live in our GitLab wiki, which renders mermaid). The flow: the user submits their email on the web app's forgot-password page. The web app calls POST /v1/password-resets on the Auth API with JSON body {"email": "..."} — no auth header, it's a public endpoint, but rate-limited: more than 5 requests per hour per IP returns 429 with a Retry-After header. The Auth API looks the user up in Postgres, and whether or not the user exists it always returns 202 Accepted so attackers can't enumerate emails. If the user exists, the Auth API publishes a reset_requested event to RabbitMQ; the Notification worker consumes it and sends the email through SendGrid (POST /v3/mail/send with an Authorization: Bearer header).
